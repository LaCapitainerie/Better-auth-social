title: Social Network
description: The social network plugin adds friends, friend requests, chat, group chat, blocked users, and posts to your auth system.
---

The social network plugin is a lightweight plugin that adds social features to Better Auth: friend requests and friends, direct chat, group chat, blocked users, and posts with likes.

## Installation

<Steps>
<Step>
### Add the plugin to your **auth** config

```ts title="auth.ts"
import { betterAuth } from "better-auth"
import { socialNetwork } from "better-auth-social" // [!code highlight]

export const auth = betterAuth({
    plugins: [
        socialNetwork() // [!code highlight]
    ]
})
```
</Step>

<Step>
### Migrate the database

Run the migration or generate the schema to add the necessary fields and tables to the database.

<Tabs items={["migrate", "generate"]}>
    <Tab value="migrate">
    ```package-install
    npx auth migrate
    ```
    </Tab>
    <Tab value="generate">
    ```package-install
    npx auth generate
    ```
    </Tab>
</Tabs>
See the [Schema](#schema) section to add the fields manually.
</Step>

<Step>
### Add the client plugin

```ts title="auth-client.ts"
import { createAuthClient } from "better-auth/client"
import { socialNetworkClient } from "better-auth-social/client" // [!code highlight]

export const authClient = createAuthClient({
    plugins: [
        socialNetworkClient() // [!code highlight]
    ]
})
```
</Step>
</Steps>

## Usage

Once the plugin is installed, the client exposes methods under the `social` namespace (e.g. `authClient.social.sendFriendRequest`, `authClient.social.getFriends`), and the server handles the corresponding API routes under `/social/*`.

## Friend Requests

Friend requests let users send, accept, or reject friendship requests.

### Send a friend request

<APIMethod path="/social/friend-request/send" method="POST" requireSession>

```ts
type sendFriendRequest = {
  /**
   * The ID of the user receiving the friend request.
   */
  receiverId: string = "user-id"
}
```

</APIMethod>

The authenticated user is the sender. You cannot send a request to yourself (unless `allowSelfFriendRequest` is enabled), to a non-existent user, to an existing friend, or if a pending request already exists.

### Accept a friend request

<APIMethod path="/social/friend-request/accept" method="POST" requireSession>

```ts
type acceptFriendRequest = {
  /**
   * The ID of the friend request to accept.
   */
  requestId: string = "request-id"
}
```

</APIMethod>

Only the receiver can accept. If `automaticBackFriend` is enabled, the friendship is created in both directions (each user has the other as friend).

### Reject a friend request

<APIMethod path="/social/friend-request/reject" method="POST" requireSession>

```ts
type rejectFriendRequest = {
  /**
   * The ID of the friend request to reject.
   */
  requestId: string = "request-id"
}
```

</APIMethod>

## Group chat

Group chats have a name, optional description, and multiple members. The creator is an admin; other members can be added by admins. By default, you can only add friends to a group (see `allowAddingUnknownMembersToGroupChat`).

### Create a group chat

<APIMethod path="/social/group-chat/create" method="POST" requireSession>

```ts
type createGroupChat = {
  /**
   * Name of the group chat.
   */
  name: string = "My Group"
  /**
   * Optional description.
   */
  description?: string = "Description"
  /**
   * User IDs of initial members (besides the creator). Must be non-empty.
   */
  memberIds: string[] = ["user-id-1", "user-id-2"]
}
```

</APIMethod>

The total number of members (creator + `memberIds`) must not exceed `maxGroupSize`. If `allowMultipleGroupChatWithSamePerson` is false, you cannot create another group with the exact same set of members.

## Hooks

You can run custom logic around social events by passing a `hooks` object to the plugin.

```ts title="auth.ts"
import { betterAuth } from "better-auth";
import { socialNetwork } from "better-auth-social";

export const auth = betterAuth({
  plugins: [
    socialNetwork({
      hooks: {
        onFriendRequestSend: async (friendRequest) => {
          await notifyUser(friendRequest.receiverId, "New friend request");
        },
        onFriendRequestAccept: async (friendRequest) => {
          await notifyUser(friendRequest.senderId, "Friend request accepted");
        },
        onFriendRequestReject: async (friendRequest) => {
          // ...
        },
        onFriendRemove: async ({ userId, friendId }) => {
          // ...
        },
      },
    }),
  ],
});
```

| Hook | When it runs |
|------|-------------------------------|
| `onFriendRequestSend` | After a friend request is created |
| `onFriendRequestAccept` | After a friend request is accepted and friendship created |
| `onFriendRequestReject` | After a friend request is rejected |
| `onFriendRemove` | After a friend is removed (both directions) |
| `onChatCreate` | After a new direct chat is created |
| `onChatMessageSend` | After a direct chat message is sent |
| `onChatMessageDelete` | After a direct chat message is soft-deleted |
| `onGroupChatCreate` | After a group chat is created |
| `onGroupChatJoin` | After a member is added to a group chat (or when creating the group) |
| `onGroupChatLeave` | After the current user leaves or is removed from a group chat |
| `onGroupChatMessageSend` | After a group chat message is sent |
| `onGroupChatMessageDelete` | After a group chat message is soft-deleted |

## Options

**allowSelfFriendRequest**: `boolean` — Allow users to send a friend request to themselves. Default: `false`.

**automaticBackFriend**: `boolean` — When a friend request is accepted, create the reverse friendship so both users see each other as friends. Default: `false`.

**allowMultipleGroupChatWithSamePerson**: `boolean` — Allow creating multiple group chats with the exact same set of members. Default: `false`.

**allowAddingUnknownMembersToGroupChat**: `boolean` — Allow adding users to a group chat even if they are not friends with the current user. Default: `false`.

**maxGroupSize**: `number` — Maximum number of members in a group chat (including the creator). Must be ≥ 2. Default: `10`.

**messageDeletionRule**: `'CANT_DELETE' | 'SENDER_ONLY_VISIBLE' | 'VISIBLE'` — How deleted messages are handled:
- `CANT_DELETE`: Users cannot delete their messages.
- `SENDER_ONLY_VISIBLE`: Only the sender still sees the deleted message (with placeholder).
- `VISIBLE`: Everyone sees that the message was deleted (placeholder for all). Default: `'VISIBLE'`.

**deletedMessagePlaceholder**: `string | ((message: GroupChatMessage) => Promise<string>)` — Text (or function returning text) shown for deleted messages. Default: `'Message has been deleted'`.

**hooks**: `SocialNetworkHooks` — Optional hooks for friend, chat, and group chat events (see [Hooks](#hooks)).
